# SRAMM Secure CI

إرشادات إعداد CI آمن للمستودع. لا تضع أسرارًا أو رموز وصول في هذا المستودع، واضبط صلاحيات Actions وقيود الفروع وبيئة النشر وفق إعداد فريقك.

## إعداد الأساس

شغّل `bash setup-foundation.sh` من داخل مستودع Git. يستخرج السكربت المالك واسم المستودع من `origin` بصيغ HTTPS أو SSH؛ إذا تعذر ذلك فسيطلبهما تفاعليًا. في البيئات غير التفاعلية مرّر `REPO_OWNER` و`REPO_NAME` أو استخدم `--non-interactive` للحصول على خطأ واضح بدل الانتظار.

يمكن تخصيص `GITHUB_BRANCH` و`RUNNER_TYPE` و`RUNNER_LABELS` و`ENVIRONMENT_NAME` و`REQUIRED_REVIEWER` و`NODE_VERSION` و`JOB_TIMEOUT_MINUTES` بمتغيرات البيئة. الافتراضات عامة ولا تتضمن اسم شخص أو بريدًا إلكترونيًا.

ينشئ السكربت `.env.example` دون أسرار، ولا ينشئ أو يقرأ أو يكتب فوق `.env`. الملفات المُولّدة الموجودة تُترك دون تغيير افتراضيًا؛ استخدم `--force` فقط بعد مراجعتها، إذ تُحفظ نسخة سابقة في `.git/foundation-setup-backups/`. لا يُستبدل hook محلي موجود. يجب أيضًا إعداد ملفات GitHub Actions وبيئات النشر والمراجعين يدويًا والتحقق منها.

إذا احتوى المستودع `package.json`، يتحقق الإعداد من إصدار Node.js المطلوب ويستخدم `npm ci` عند وجود ملف قفل، أو `npm install` مع تحذير عند غيابه. لا ينشئ `package.json` لمستودع لا يحتويه.

## حماية الملفات الحساسة

نسخة hook الموزعة موجودة في `scripts/hooks/pre-commit`. يثبّتها الإعداد محليًا فقط إذا لم يكن هناك hook سابق. Git لا يوزع hooks تلقائيًا؛ لذلك على كل مطور تثبيت hook، كما أن hooks المحلية يمكن تجاوزها ولا تغني عن ضوابط الحماية في الخادم.

يفحص hook المسارات staged فقط، ويرفض `.env` وملفات `.env.*` المحلية (مع السماح بـ`.env.example`) ومحتويات `.secrets` وامتدادي `.key` و`.pem`. لا يُضاف `package-lock.json` إلى `.gitignore`.

## الاختبارات

شغّل `bash tests/test-setup-foundation.sh` لاختبار اكتشاف remote وسلامة الملفات المحلية وسلوك npm وأسماء الملفات الحساسة.
